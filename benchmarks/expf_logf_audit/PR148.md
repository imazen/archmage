## What PR148 fixes and what still fails

The float-zero classifier fixes `log2(-0)` to negative infinity. The rational
LOWP log2 restores its cheaper graph. Generation, registry/token validation and
static soundness checks pass. The inherited failures remain:

- `cargo check -p magetypes --no-default-features` fails at three scalar
  `f32::mul_add` sites in log1p.
- 32/64 valid const configurations per family panic in debug. The shared table
  includes LEGACY in its key without corresponding arms, and drops BACKEND.
  Runtime adapters support only 10/64 builder configurations.
- Full/Specials plus AssumeValid removes required exceptional-result handling.
  Accepting a domain and assuming that domain must agree on accepted inputs.
- `log1p(-0)` loses its sign; explicit scalar token errors return mask 15 instead
  of lane 1. Five independent tests still fail in release, six in debug.
- The advertised two-FMA LOWP exponential branch remains unreachable. Activating
  it over the existing range exceeds the 0.56% relative-error target near 128.
- Legacy bit-compatibility claims remain false for ordinary refit inputs. The
  owner does not require that compatibility; remove the claim, not the witnesses.

Current observed GitHub status at this head: 32 successful and 24 failed checks.
The independent test package deliberately retains the failing contract witnesses.
They are not skipped or counted as passing shipping tests.

The LOWP log2 revert has a meaningful quality cost. Its sampled maximum absolute
error is 6.263690409e-6, but its bias at 1 makes ULP/relative error unsuitable near
zero. Through log1p, input +0 produces -1.2951142025485751e-6 and input 1e-8
produces -1.285114194615744e-6. Do not call this a violation of a loose absolute
log2 budget; it is a sign/near-zero tradeoff that makes the same LOWP log1p wrapper
unattractive. Use a separately validated small-x kernel or withhold that profile.

## Concrete further fix: one ordered comparison

Replace `(x < 0) | (x != x)` by ordered `x >= 0`, and reverse the corresponding
blend. It accepts both zeros, rejects negative values and NaNs, and retains the
separate zero/infinity result handling. The review branch also applies the same
classification to generated ScalarToken legacy log methods and their generator.
That changes ScalarToken NaN classification to NaN, matching the native method;
ordinary finite polynomial results are unchanged.

Independent exact models match 3,328,000 loop outputs across 1,600 policy
segments, before and after this patch. Full NaN scans cover all 16,777,214 signed
quiet/signaling NaN encodings, in bounded eight-lane storage, for legacy checked
log, configured Log Specials and configured Exp Full. Native and ScalarToken
runs on x86 and M6 each return zero non-NaN results in all three paths. Payload
identity and floating exception flags were not tested.

## Which options earn their existence?

The policy study freezes 64 timing cells, 24 literal configurations plus one
explicit-token scalar lane-map arm per group, and 50 retained interleaved rounds.
The 16 Full/Specials+AssumeValid configurations are excluded from speed promotion
because of the known correctness defect; they remain in contract tests. Of the
64 cells, 9 AMD and 60 Intel cells are clean and confined. M6 has zero.

1. **Remove public LegacyMidp/LegacyLowp choices.** They are coefficient-fit
   selectors, not useful precision contracts for this task. LOWP log2's two
   fits are now identical. Keep frozen predecessor implementations in benchmark
   tools. A legacy coefficient's occasional timing difference does not establish
   a generally useful speed profile. Canonical MIDP improves the sampled exp2
   core from 1.3293 to 0.7310 ULP and log2 from 3.4296 to 2.0231 ULP.
2. **Keep portability as a semantic choice, normalize it inside known-fused
   kernels.** Scalar/non-FMA backend arithmetic can be much cheaper. A V3/NEON
   fused kernel need not instantiate two copies of the same graph. BackendDependent
   is not automatically faster in every current monomorph: the clean Intel
   x8/4096 exp2 LOWP policy arm takes 2359.604 versus BitExact 2262.482 ns,
   ratio CI 1.03795–1.04853. Generated call shape still matters.
3. **Keep validation when it actually rejects something.** Intel x8/4096 exp2
   LOWP AssumeValid takes 2262.482 versus Checked 2351.729 ns, CI
   0.95795–0.96649. Other arms show little saving. Full/Specials currently
   accepts every f32 classification; its validation switch should not remove
   result semantics. Under that classification contract it is redundant. If a
   new accurate profile rejects subnormals, validation becomes meaningful again.
4. **Move execution selection to the entry-point layer.** Public array Caller
   currently reconstructs ScalarToken even inside a native caller. The scalar
   token lane-map alternative is not a performant vector API: Intel x8/4096
   MIDP exp2 takes 136862.252 versus Automatic array 2680.806 ns. Preserve the
   real caller token in a typed vector kernel and dispatch once above the loop;
   do not map public scalar calls over lanes or probe features in each vector.
5. **Make range a real contract and optimization input.** Finite Bounded inputs
   still clamp today; AssumeValid alone cannot remove that work. A normal-output
   range can remove clamps and permit a cheaper LOWP polynomial, as below.

For the current all-f32 Full/Specials classification contract, removing legacy
fits, treating execution as an entry point and removing redundant Full validation
reduces **64 flag combinations to 12 semantic math profiles per family**:
2 precision × 2 portability × 3 domain/validation states. This is a design count,
not a claim that those twelve corrected implementations are already shipped.
Rejecting additional inputs would change that count and must be explicit.

## Range experiment: genuine speed/quality choices

The benchmark-only `normal_range` binary tests exp2 on **[-126,127.5)**, rejecting
the whole vector with exact lane masks when Checked. It includes endpoints,
subnormal arguments near zero and rejection tests for NaNs/infinities and both
out-of-range rails. An assumed preset has the same accepted-domain graph.

An independent rational mirror matches all 55,566 evaluated outputs (3,087 inputs
× 9 graph arms × ScalarToken/native). Directed MPFR256 sample maxima:

| Graph | Fused maximum | Backend separate maximum |
|---|---:|---:|
| MIDP degree 6 | 0.730997 ULP | 1.020275 ULP |
| LOWP floor cubic | 0.0299693% relative | not sampled here |
| LOWP round quadratic | 0.3060013% relative | 0.3060013% relative |

The quadratic uses two FMAs rather than three; it fits the existing 0.56% LOWP
sample target within this range. No exhaustive maximum-error proof was performed.
It cannot be substituted for the wider finite-clamped graph without a new range
contract. [PR147's rail witnesses](REVIEW.md) still exceed the bound outside it.

All eight Intel range timing cells are clean, confined and contain all 50 pairs.
The eight AMD counterparts are all resource-flagged and retained as inadmissible.
For native x8/64 independent streams:

|---|---:|---|

| Normal MIDP fused AssumeValid token kernel | 8.587 | 0.61874–0.62329 vs main MIDP |
| Normal MIDP fused Checked token kernel | 10.843 | 0.77798–0.79144 vs main MIDP |
| Frozen main exp2_lowp | 7.926 | reference |
| Normal LOWP cubic fused AssumeValid token kernel | 6.368 | 0.79639–0.81114 vs main LOWP |

The fused MIDP and quadratic LOWP assumed kernels beat their frozen legacy
baselines in all four native cells (64/4096, stream/chain). They fail the same
cost bound in all four ScalarToken cells, where forced software fusion costs.
For ScalarToken x8/64 streams, MIDP fused is 339.953 ns, relaxed 91.148 ns and
legacy 152.116 ns; LOWP quadratic fused is 173.803 ns, relaxed 82.376 ns and
legacy 119.022 ns. Relaxed/main ratio CIs are 0.58446–0.62181 for MIDP and
0.67909–0.70450 for LOWP. Those two direct relaxed/main contrasts were added
after the first analysis; the original 14-edge analysis is preserved separately.
All measurements use the same frozen interleaved raw observations.

Thus portability has a real scalar cost, while native fused execution can share
code. Range and precision buy identifiable work removal. Keep these distinctions;
do not promise that every exposed Boolean is faster when enabled.
