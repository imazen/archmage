# Inferred wrappers, dispatcher selectors and parent proofs

Implemented on the unpublished attune draft; legacy spellings remain supported.
These changes do not alter omission defaults for inline attributes.

## Definition conventions

```rust,ignore
#[attune]
fn work_v3(x: u32) -> u32 { x + 1 }

#[attune]
fn work_v3_t(x: u32) -> u32 { x + 1 }
```

The first is a direct V3 function. The second is a proof boundary: its exposed
signature becomes `work_v3_t(proof: X64V3Token, x: u32) -> u32`, with a private
V3 implementation. It does not become callable from arbitrary code without proof.
The boundary keeps its separate always-inline policy; the operation body keeps
its normal inline hint. No additional public `work_v3` function is generated by
that second definition.

A written matching proof parameter retains its position and generic bounds.
A written `Token` parameter specializes to the inferred tier's concrete token;
`Token` call markers remain available during contextual call rewriting. A proof
whose declared features differ from the suffix is rejected; explicit `wrap`
continues to infer from the parameter for arbitrary names. Longest registered
suffixes win, including `_v3_gfni_crypto_t`. Explicit tier and `wrap` arguments
override name inference.

Methods receive an injected proof immediately after `self`. Receiverless
associated functions still need `in_impl`; trait wrappers retain the existing
`in_trait`/`_self` placement restrictions. Inferred proof wrappers do not accept
`define(...)`; use a generated family when aliases are needed there.

## Dispatchers

`dispatch` and `_` are synonyms inside `make(...)`, including visibility and
inline overrides. Both produce the same output.

```rust,ignore
#[attune(make(dispatch))]
#[attune(make(dispatch, +v4(avx512)))]
#[attune(make(_, +v4(avx512), -neon))]
```

These are alternative attributes, not a stack. Dispatcher-only modifiers start
from V3, NEON, WASM128 and scalar. Additions produce private implementations;
they do not silently expose direct or proof APIs. Removals work even when a tier
was absent. A dispatcher requires an ungated scalar fallback; removing or gating
it is rejected. Duplicate dispatcher selectors are also rejected.

Wildcard modifiers continue to select the wildcard's output forms. For example,
`make(_*, +v4(avx512), dispatch)` exposes direct variants as well as a dispatcher.
Every interface for one tier must use the same feature gate. Conflicting gates
remain an error. Use `+v4` without `_t` for a hidden dispatcher addition; an
explicit `_v4_t` requests an exposed proof wrapper.

## Implicit parent proof

Inside an annotated feature body, `attuned!` uses the feature context first for
covered candidates. These remain direct calls; inheriting proof does not force
a trampoline onto an already covered fast path.

For a candidate beyond that context, it can reuse one named proof parameter:

```rust,ignore
#[attune(scalar)]
fn select<T: archmage::IntoConcreteToken>(proof: T, x: u32) -> u32 {
    attuned!(work(x), [_v3, _scalar])
}
```

This has no CPU detection. A concrete parent token can prove the same tier or a
registry ancestor through its safe extraction method. A generic parent bounded
by `IntoConcreteToken` uses that trait's existing exact-type selection semantics;
it does not add conversions from every possible stronger concrete token. The
remaining candidates must supply a guaranteed fallback. Concrete proof can itself
supply that guarantee; a fallible generic type test cannot.

Inference recognizes qualified concrete tier-token types and `IntoConcreteToken`
bounds in inline generics, where clauses, and `impl Trait`. Named borrowed proof
parameters are copied. The copy is captured hygienically at function entry only
when needed, before user-local shadowing. Nested function/items do not inherit it;
closures within the function use the enclosing context. Multiple eligible proof
parameters require `using(token)` when a call needs inherited proof; already
covered calls do not need that choice. Explicit `using(...)` wins and is evaluated
once. `reattune!` retains runtime reselection unless given explicit `using(...)`.

Ambiguity diagnostics follow the candidate's architecture and feature gates,
including guards for earlier guaranteed choices. A foreign or disabled candidate
cannot require a parent-proof choice before an available scalar fallback.

The same contextual rewrite is shared by compatible legacy feature attributes.
Ordinary unannotated functions cannot provide their signature to a function-like
macro: keep `using(token)` there. Inference does not inspect enclosing source,
resolve arbitrary Rust type aliases, select local-variable proofs, or invent an
`IntoConcreteToken` bound. Feature-only generic bounds remain sufficient for
covered direct calls.

## Verification and cost boundary

`attune/convention_tests.rs` checks emitted attributes, signatures, visibility,
feature gates, diagnostics, and absence of CPU probes/direct-call wrappers.
`tests/attune_conventions.rs` checks real compilation and execution under
`forbid(unsafe_code)` and `deny(warnings)`, including generic and borrowed proofs,
shadowing, explicit overrides, concrete downgrades, methods, and legacy callers.
The suite is run with AVX-512 Cargo support both disabled and enabled. This is
host execution, not an AVX-512 runtime coverage claim.

Discovery is lazy: only a call that needs inherited proof scans the signature.
Bodies remain token streams; no enclosing-source scan or full body-AST parse was
introduced. This design property alone is not proof of zero compile-time cost;
the draft's broader cold-build acceptance gate remains separate.
