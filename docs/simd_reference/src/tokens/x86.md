# x86-64 Tokens

`X64V1Token` (alias `Sse2Token`) is the x86-64 baseline, SSE and SSE2; its
`summon()` always succeeds on x86-64. `X64CryptoToken` is V2 plus PCLMULQDQ and
AES, and `X64V3CryptoToken` is V3 plus those and VPCLMULQDQ and VAES.

## X64V2Token

**LLVM Level:** x86-64-v2
**Features:** SSE3, SSSE3, SSE4.1, SSE4.2, POPCNT, CMPXCHG16B
**CPUs:** Intel Nehalem (2008)+, AMD Bulldozer (2011)+
**Register width:** 128-bit (XMM)

```rust
use archmage::{X64V2Token, SimdToken, arcane};

if let Some(token) = X64V2Token::summon() {
    process_sse(token, &data);
}
```

The V2 level adds the most commonly useful SSE extensions beyond baseline. If you only need 128-bit operations with SSE4.2, this is the token.

## X64V3Token

**LLVM Level:** x86-64-v3
**Features:** All V2 + AVX, AVX2, FMA, BMI1, BMI2, F16C, LZCNT, MOVBE
**CPUs:** Intel Haswell (2013)+, AMD Zen 1 (2017)+
**Register width:** 256-bit (YMM)

```rust
use archmage::{X64V3Token, SimdToken, arcane};

// X64V3Token is the recommended baseline for most SIMD work
if let Some(token) = X64V3Token::summon() {
    process_avx2(token, &data);
}
```

**Aliases:** `Desktop64` (`Avx2FmaToken` is a deprecated alias)


### Key capabilities at this tier

- 256-bit integer operations (AVX2)
- Fused multiply-add (FMA3) — `a * b + c` in one instruction
- Bit manipulation (BMI1/BMI2) — `pdep`, `pext`, `tzcnt`, `lzcnt`
- Half-float conversion (F16C) — `f16 ↔ f32`

## X64V3GfniCryptoToken

**Features:** All X64V3CryptoToken features + GFNI
**CPUs:** Intel Alder/Raptor/Meteor/Arrow/Lunar Lake, Sierra Forest, AMD Zen 4+
**Register width:** 256-bit (YMM)

```rust
use archmage::{SimdToken, X64V3GfniCryptoToken, arcane};

if let Some(token) = X64V3GfniCryptoToken::summon() {
    process_gf2(token, &data);
}
```

Provides the unmasked 128/256-bit GFNI forms without requiring AVX-512. Use it
for GF(2^8) multiplication, affine transforms, Reed-Solomon erasure coding, and
binary-field arithmetic.

## X64V4Token / Server64 / Avx512Token

**LLVM Level:** x86-64-v4
**Features:** All V3 + PCLMULQDQ, AES, AVX-512F, AVX-512BW, AVX-512CD, AVX-512DQ, AVX-512VL
**CPUs:** Intel Skylake-X (2017)+, AMD Zen 4 (2022)+
**Register width:** 512-bit (ZMM)
**Cargo feature:** `avx512` for `import_intrinsics` and magetypes' native 512-bit backends; the token itself needs none

```rust
use archmage::{Server64, SimdToken, arcane};

if let Some(token) = Server64::summon() {
    process_avx512(token, &data);
}
```

**Aliases:** `Server64` (preferred), `Avx512Token`

AVX-512 doubles width again to 512-bit and adds mask registers for predicated operations. The "VL" subset means these new instructions also work on 128/256-bit registers, so you get better codegen even at smaller widths.

### Frequency throttling

**Intel:** Heavy 512-bit usage can downclock the CPU by 100-200 MHz on some models. For sustained workloads, 256-bit may actually be faster due to higher clock speeds. Profile your workload.

**AMD Zen 4 and Zen 5:** No significant throttling. Zen 4 runs 512-bit operations through 256-bit units; Zen 5 desktop and server parts have full 512-bit datapaths.

## X64V4xToken

**Features:** All V4 + VPOPCNTDQ, IFMA, VBMI, VNNI, VBMI2, BITALG, VPCLMULQDQ, GFNI, VAES
**CPUs:** Intel Ice Lake (2019)+, AMD Zen 4 (2022)+
**Aliases:** `Avx512ModernToken`

```rust
use archmage::{X64V4xToken, SimdToken};

if let Some(token) = X64V4xToken::summon() {
    // Modern extensions: VNNI for ML inference, VAES for crypto, etc.
}
```

Adds specialized instructions for ML inference (VNNI), cryptography (VAES, VPCLMULQDQ, GFNI), and bit manipulation (VBMI, BITALG). It does not include AVX512-BF16. Only use if you specifically need these extensions.

## Avx512Fp16Token

**Features:** All V4 + AVX-512 FP16
**CPUs:** Intel Sapphire Rapids (2023)+

```rust
if let Some(token) = Avx512Fp16Token::summon() {
    // Native FP16 arithmetic (not just conversion)
}
```

Native half-precision float arithmetic. Distinct from F16C (which only converts between f16 and f32) — this does actual `f16` math in hardware.

## Downcasting

Higher tokens convert to lower ones with extraction methods (`.v3()`, `.v2()`, ...), and satisfy tier-trait bounds such as `impl HasX64V2`. This is free — no runtime cost:

```rust
#[arcane(import_intrinsics)]
fn needs_v3(token: X64V3Token, data: &[f32; 8]) -> f32 { ... }

#[arcane(import_intrinsics)]
fn has_v4(token: Server64, data: &[f32; 8]) -> f32 {
    // V4 is a superset of V3, so the call inlines
    needs_v3(token.v3(), data)
}
```
